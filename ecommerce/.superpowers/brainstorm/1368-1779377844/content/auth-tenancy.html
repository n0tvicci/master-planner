How users, workspaces, roles, and permissions are structured

WorkspaceMember

Controls who can do what inside a workspace.

Workspace Roles (RBAC)

Owner
  • ✓ Full admin
  • ✓ Buy credits
  • ✓ Invite / remove members
  • ✓ Delete workspace
  • ✓ All product access
Admin
  • ✓ Buy credits
  • ✓ Invite members
  • ✓ All product access
  • ✗ Cannot delete workspace
  • ✗ Cannot remove Owner
Member
  • ✓ All product access
  • ✓ View credit balance
  • ✗ Cannot buy credits
  • ✗ Cannot invite
  • ✗ Cannot manage workspace

Auth Flow

1
User signs up → personal workspace auto-created → JWT issued (contains user_id + active workspace_id)
2
JWT stored in httpOnly cookie (not localStorage — prevents XSS token theft)
3
Every API request carries the JWT → middleware resolves user + workspace + role in one DB query
4
User can switch active workspace → new JWT issued with updated workspace_id
5
Team invites: Owner/Admin sends invite link (signed token, 48h expiry) → invitee clicks → joins workspace as Member
