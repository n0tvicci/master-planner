Section 4 (Updated) — AI Automation Pipeline

Corrected per-product inputs & outputs

Job Lifecycle — Shared Across All 3 Products

1
Client submits form + optional file upload → API checks + deducts credits atomically → inserts job row (queued) → enqueues to BullMQ → returns job_id immediately
2
Worker picks up job → status → processing → provider adapter calls the active AI provider with job payload
3
Success: result saved (text in DB / images + videos in R2) → status → completed → client notified via WebSocket
4
Failure: BullMQ retries 3× with backoff → if exhausted → status failed → credits auto-refunded in ledger → client notified
queued → processing → completed or failed
📝 Text Writer
Input (seller provides)
  • Product name
  • Basic product details
  • Marketplace (Shopify / Amazon / Shopee)
Output
  • SEO-optimized title
  • Product description (HTML-ready)
  • Bullet point highlights (×5)
Marketplace selection shapes the tone, length, and format rules (e.g. Amazon title limits, Shopee style)
🖼️ Image Generator
Input (seller provides)
  • Raw product image (upload)
  • Style (studio / lifestyle / minimalist)
  • Background color or scene
  • Aspect ratio (1:1 / 4:3 / 16:9)
Output
  • Professional product image
  • Signed download URL (R2/S3)
Image-to-image: seller's raw photo → AI-polished product visual. No prompt engineering needed.
🎬 Video Generator
Input (seller provides)
  • Product images (1–5 uploads)
  • Motion style (rotate / zoom / showcase)
  • Duration (3s / 5s / 10s)
  • Target platform (TikTok / Reels / YouTube)
Output
  • Product video clip
  • Signed download URL (R2/S3)
Multi-image to video. Platform selection sets aspect ratio & format automatically.

Provider Adapter — Swap Providers via Config, Not Code

interface AIProvider { generate(payload): Promise<Result> }
Each provider implements one interface. Active provider set per product via ACTIVE_TEXT_PROVIDER, ACTIVE_IMAGE_PROVIDER, ACTIVE_VIDEO_PROVIDER env vars.
