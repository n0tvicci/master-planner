Section 4 — AI Automation Pipeline

Job lifecycle · Provider adapter · Result delivery · Per-product flow

Job Lifecycle (all three products share this flow)

1
Client submits job via REST → API validates input, checks + deducts credits atomically, inserts job row with status queued, enqueues to BullMQ → returns job_id immediately (no waiting)
2
Worker picks up job → updates status to processing → calls provider adapter with job payload → adapter selects configured provider and calls AI API
3
On success: result stored (text in DB, images/videos uploaded to R2/S3) → job status set to completed → result URL/data written to job row → client notified via WebSocket or SSE
4
On failure: BullMQ retries up to 3× with exponential backoff → if all retries exhausted, status set to failed → credit refund inserted into ledger → client notified
5
Client polls GET /jobs/:id OR listens on WebSocket channel workspace:{id} for real-time status updates — no page refresh needed
queued → processing → completed or failed

Provider Adapter Pattern — swap AI providers via config, not code

interface AIProvider { generate(payload): Promise<Result> }
Each provider implements the same interface. Workers only call the interface — never the provider directly. Active provider set per product via environment config.

Per-Product Job Inputs & Outputs

📝 Text Writer
Input:
  • Product name
  • Category
  • Key features (bullet list)
  • Tone (professional / fun / luxury)
  • Target platform (Amazon / Shopify / Etsy)
Output:
  • SEO title (≤80 chars)
  • Product description (HTML-ready)
  • Bullet points (x5)
🖼️ Image Generator
Input:
  • Product name
  • Style (studio / lifestyle / minimalist)
  • Background color / scene
  • Reference image (optional upload)
  • Aspect ratio (1:1 / 4:3 / 16:9)
Output:
  • Generated image URL (R2/S3)
  • Download link (signed URL)
🎬 Video Generator
Input:
  • Product name
  • Source image (upload or from Image module)
  • Motion style (rotate / zoom / showcase)
  • Duration (3s / 5s / 10s)
  • Platform (TikTok / Reels / YouTube)
Output:
  • Video URL (R2/S3)
  • Download link (signed URL)
