3 Architecture Approaches

Pick the one that fits your goals — scalability, speed-to-demo, and AWS readiness

A

Simple Monolith

One Express app handles everything — auth, billing, all three AI products — backed by a single PostgreSQL database. Synchronous API calls to AI providers.

Pros

  • Fastest to build and demo
  • Easy to reason about
  • Zero infra complexity

Cons

  • AI calls block HTTP threads (video = minutes)
  • Hard to scale individual products
  • Poor UX for slow generations
  • AWS migration is messy later
B ⭐ Recommended

Modular Monolith + Job Queue

One Express app organized into clean modules (auth, billing, text, image, video) with a Redis + BullMQ job queue for async AI generation. Jobs run in background workers, clients poll for results.

Pros

  • Non-blocking UX — video jobs run in background
  • Modular structure = clean AWS migration (modules → Lambda/ECS)
  • BullMQ → SQS is a 1:1 swap on AWS
  • Retry logic built into queue
  • Still simple enough for a solo/small team

Cons

  • Redis adds one more service to run locally
  • Slightly more code to wire up jobs vs. direct calls
C

Microservices from Day 1

Separate services: API Gateway → Auth Service, Billing Service, Text Service, Image Service, Video Service. Each deploys independently. Message bus (RabbitMQ/Kafka) for inter-service communication.

Pros

  • Maximum scalability
  • Services deploy independently
  • Already AWS-native in structure

Cons

  • Over-engineered for current team size
  • 3–5× more code and infra to set up
  • Distributed tracing, service discovery, network errors
  • Wrong for a demo stage
