Data Flow v2 — With Tool Use Loop

Updated to show iterative NinjaOne script execution driven by Claude's tool calls

PHASE 1 — INCIDENT INITIATION (unchanged)
IT Admin submits device + problem → API Gateway → Orchestrator Lambda → creates incident ID → NinjaOne triggered for initial log collection (optional) → SQS job enqueued → UI gets incident ID immediately
PHASE 2 — SESSION BOOTSTRAP
1 Worker Lambda reads SQS job → loads Script Library from DynamoDB (all available scripts + descriptions)
2 Queries Bedrock Knowledge Base with problem description → retrieves top-K similar past incidents + known fix docs
3 Builds first Converse API call:
system: "You are an IT diagnostic AI. Analyze logs and investigate issues. Tools available: [list of scripts]. Always ask for more data before concluding."
user: "Device: WIN-PC-0042. Problem: Adobe CC install failing 1603. Initial logs: [s3 contents]. Past similar incidents: [KB results]"
tools: [ { name: "run_script", description: "Run a NinjaOne script on the device", input_schema: { script_name, device_id } } ]
🔄 PHASE 3 — TOOL USE LOOP (repeats until Claude issues final answer)
A Claude responds with a tool call (not a final answer yet):
{ tool: "run_script", input: { script_name: "check_connectivity", device_id: "WIN-PC-0042" } }
B Worker Lambda intercepts tool call → looks up ninja_script_id in Script Library → calls NinjaOne API → waits for script completion → fetches output from S3
C Tool result appended to conversation and sent back to Claude:
{ tool_result: "DNS: OK, Gateway: OK, Port 443 to adobe.com: BLOCKED by firewall rule #47" }
D Claude may call another tool or issue its final answer. Loop repeats for each tool call. Conversation history accumulates in DynamoDB each round.
Example multi-step investigation:
Turn 1: Claude calls get_install_logs → gets MSI error 1603
Turn 2: Claude calls check_connectivity → finds port 443 blocked
Turn 3: Claude calls check_firewall_rules → confirms rule blocking Adobe CDN
Turn 4: Claude issues final answer with all evidence assembled
PHASE 4 — FINAL REPORT DELIVERY
4 Claude issues final structured response stored to DynamoDB + S3:
ROOT CAUSE: Adobe CC installer cannot reach CDN (port 443 blocked)
EVIDENCE: MSI log error 1603 + connectivity check (port 443 blocked by rule #47)
KB MATCH: Similar incident INC-2025-0312 resolved by firewall rule exception
RECOMMENDED STEPS: 1. Open firewall exception for Adobe CDN IPs 2. ...
5 UI notified → IT Admin reviews full report including which scripts were run and what they found
6 IT Admin acts manually. Can ask follow-up questions in the same session. After resolution, can add fix to Knowledge Base.
Scripts Claude can call (examples):
  • get_install_logs
  • get_windows_update_logs
  • check_connectivity
  • check_firewall_rules
  • check_disk_space
  • get_running_services
  • check_proxy_settings
  • get_event_viewer_errors
  • + any new script you add to NinjaOne
Safety guardrails on tool use:
  • Scripts are read-only / diagnostic only — no remediation scripts in the library
  • Max script calls per session capped (e.g. 10) to prevent runaway loops
  • Each script call logged to DynamoDB with timestamp
  • IT Admin can see exactly which scripts ran and their raw output
