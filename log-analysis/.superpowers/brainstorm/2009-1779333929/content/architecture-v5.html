S3 output path convention:
logs/{ninja_device_id}/{incident_id}/{script_name}/output.txt Lambda generates pre-signed PUT URL before firing the script. Script receives URL as parameter and uploads directly. Lambda reads from the known path — no guessing.
NinjaOne script contract (required):
param([string]$output_url, [string]$incident_id)
$output = "... diagnostics ..."
$bytes = [Text.Encoding]::UTF8.GetBytes($output)
Invoke-WebRequest -Uri $output_url -Method PUT -Body $bytes Every script must follow this pattern. Without it, S3 stays empty and the poller times out.
Job status polling:
get_job_status() → (status, message) Returns tuple in one API call. FAILED branch uses the message directly — no second fetch. Poll timeout = 120s max (exponential backoff). 4 scripts × 120s = 480s well within 900s Worker Lambda limit.
